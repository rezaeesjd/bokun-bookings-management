# Version 1.3.0 — predefined-key dashboard login with roles

The booking dashboard no longer relies on the WordPress login, and the Bookings
view is no longer public. Everything is now behind a self-contained key login,
with three roles.

## Roles

- **Admin** — full access, including the Analytics tab and settings.
- **Booking manager** — everything except the Analytics tab; full booking and
  messaging write access (change result/payment, Message client, edit product
  tags, run imports, use the Messages inbox).
- **Generic** — the read-only Bookings view (what used to be public).

Three users are seeded by default: Bardi (admin), Johnna (booking), SJD
(generic). Each signs in with a simple key.

## How it works

- Visiting the dashboard without a session shows a **key login screen**; the
  public sees nothing else. A small account bar ("Signed in as … · Sign out")
  sits above the dashboard for key sessions.
- Identity is a **signed, HttpOnly cookie** (HMAC over the user id, expiry and a
  hash of the key, keyed by the WordPress auth salt). Tampering, expiry
  (12 hours), and key rotation all invalidate a session. Failed logins are
  throttled per IP.
- A logged-in **WordPress administrator** (`manage_options`) always resolves to
  the admin role — a lockout failsafe, independent of the keys.
- Because the dashboard — and the AJAX/REST nonces it emits — now render only for
  a resolved actor, the existing WordPress nonces keep protecting the write
  endpoints from CSRF (the public never receives a nonce).

## Managing keys

A new **Dashboard Access** screen (Bókun menu → Dashboard Access, admin only)
lists the users, their roles and keys, and lets you rename users, reassign
roles, and regenerate keys. Rotating a key signs that person out of any active
session.

## Capability wiring

The view gating and every write path now route through role capabilities:
`view_bookings`, `manage_bookings`, `view_messages`, `manage_messages`,
`view_analytics`, `manage_settings`. The Analytics and Business Results tabs are
admin-only; staff booking controls and the Messages inbox are booking + admin.

No booking data, analytics, chart logic or UI content changed — only who can see
and do what.
