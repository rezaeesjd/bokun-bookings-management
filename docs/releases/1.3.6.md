# Version 1.3.6 — Analytics records: links column + inline Refunded toggle

Two additions to the **Records** table in the Analytics tab.

## Links column

A single minimal **Links** column per record: `Viator · Bokun · WP · Booking`,
each a link when available:

- **Viator** — the Viator supplier conversation for the booking (when the
  booking carries a channel reference).
- **Bokun** — the booking's sale in Bokun (when it has a parent booking id).
- **WP** — the booking's WordPress edit screen.
- **Booking** — the booking's single front-end page (`/bokun-booking/<slug>/`).

The URLs are derived per record at render time (not stored as source columns);
post caches are primed once so the extra lookups stay cheap. The column is not
sortable.

## Inline Refunded toggle (Status column)

The **Status** column now carries a one-click **Mark refunded / Un-mark**
control next to the status. It drives the existing durable **channel-refund
marker** (`_user_channel_refunded`) — the mechanism for a refund that happened
in the sales channel (e.g. Viator) but never reached Bokun, so Bokun keeps
reporting CONFIRMED. Marking it:

- applies the authoritative "Refunded" marker that every future Bokun import
  preserves,
- forces the effective status to REFUNDED and drops the booking out of gross
  and net revenue,
- re-syncs the analytics row immediately.

This reuses the same server action as the "Mark a booking refunded (channel)"
box on the Analytics Data screen (admin-only, nonce-protected). After a change
the page reloads so the records, totals and all revenue metrics reflect the
re-synced row; the `#analytics` hash keeps the reload on this tab. The control
is shown only to users who can manage the site. No free status rewriting —
Confirmed/Cancelled remain Bokun-authoritative (a manual change there would be
overwritten on the next import); only the durable channel-refund override is
exposed.
