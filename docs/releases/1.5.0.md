# Version 1.5.0 — Tour leader column, travel-date periods, full-data search

Three Analytics improvements.

## 1. Tour leader name in the Records table

The Records table gains a **Tour leader** column (the booking's lead traveller
/ main contact — the only person name in the booking payload). It's populated
from a new `customer_name` source column (`_first_name` + `_last_name`), so it
is also searchable like every other column.

- Schema bump: `BOKUN_ANALYTICS_DB_VERSION` → **1.6.0** adds
  `customer_name VARCHAR(191)`; existing installs auto-schedule a one-time
  rebuild to backfill it (Rebuild now is the fallback when wp-cron is off).
- Analytics is admin-only (`view_analytics`), so the name stays within the
  staff view that already shows confirmation codes and external references.

## 2. Date-range presets can apply to created **or** travel date

A new **"Range by" toggle** (Created · Travel) sits above the 7d / 30d / 3m /
6m / All presets. The presets and the default view apply to whichever basis is
selected:

- Switching basis carries the current window over to the chosen date and clears
  the other, so the same range simply moves from created to travel (or back).
- The explicit Created / Travel from–to date pickers are unchanged, and editing
  either clears the preset highlight.
- Reset returns the basis to Created and re-applies the default view.

## 3. Search spans all data, ignoring the active date window

Typing in the Analytics search box now searches the **entire retained dataset**
— the active date window (including the default last-3-months view) is bypassed
while a query is present, so a booking from any month is found. Facet
selections still apply alongside the search. The filter summary shows
"· search spans all dates" while a query is active.

## Tests
