# Version 1.3.2 — "Current user" reflects the key session

The dashboard footer's **Current user** was derived only from
`wp_get_current_user()`, so a key-session user (booking/admin/generic, with no
WordPress account) showed as **"Guest user"** — even though the booking-history
action log (fixed in 1.3.0) already attributed their actions to their mapped
name. The two disagreed.

The "Current user" indicator now prefers the resolved access actor's name, so it
matches the history attribution: Bardi / Johnna / SJD read as themselves. It
still falls back to the WordPress display name, then to "Guest user" only when no
actor is resolved.
