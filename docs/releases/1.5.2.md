# Version 1.5.2 — Booking pages use the key login, not the old name gate

Single booking pages and the booking archive were still protected by the
legacy **"Team Member Verification — enter your name"** overlay, where typing
*any* name set a cookie and granted access. That gate is now wired to the
**key-based access system** (`includes/bokun-access.php`) introduced in 1.3.0,
so it matches the dashboard.

## What changed

- **Authorization** for `bokun_booking` single/archive pages now requires the
  `view_bookings` capability — i.e. a signed-in Generic, Booking, or Admin key,
  or a logged-in WordPress admin. Merely entering a name no longer authorizes
  anyone.
- **The gate screen** now shows the same **Dashboard sign-in** (access key)
  form as the rest of the dashboard, instead of the name overlay. Signing in
  there sets the normal 30-day remembered session, so a booking link opened on
  a trusted device stays accessible.
- The gate page is `noindex,nofollow` and returns `403` until authorized.

## Notes

- The `team_member` taxonomy (and the dashboard's "Filter by team member")
  is unchanged — only the *access gate* was swapped.
- The legacy `[team_member_field]` / `[team_member_reset_button]` shortcodes
  remain registered for backward compatibility but are no longer part of the
  booking-page gate; the gate no longer renders that overlay.

## Tests

WordPress integration suite gains gate coverage (anonymous denied, non-staff
login denied, WordPress admin admitted via the access system, the gate renders
the key sign-in form, and the retired name overlay is gone). Full suite green.
