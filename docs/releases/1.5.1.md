# Version 1.5.1 — Stay signed in on trusted devices

The dashboard key login previously expired after **12 hours**, so users had to
re-enter their key almost every time they opened the dashboard. Sign-in is now
persistent on a trusted device.

## What changed

- **Longer session.** The signed login cookie lasts **30 days** (filterable via
  `bokun_access_lifetime`) instead of 12 hours.
- **Sliding expiry.** An actively used, remembered device has its cookie
  re-issued once it is more than a day old, so a device that keeps visiting
  **never gets logged out**; an idle device still expires after the full
  window.
- **"Keep me signed in on this device" checkbox** on the login screen, ticked
  by default. Unticking it issues a **browser-session cookie** that ends when
  the browser closes — for shared or public computers.

## Security

- The cookie stays HttpOnly, Secure (on HTTPS), SameSite=Lax, and HMAC-signed
  over `id | expires | remember | hash(key)` with `wp_salt('auth')`. A tampered
  id, expiry, remember flag, or signature is rejected.
- **Regenerating a key still signs out all of that user's existing devices**
  immediately (the signature no longer matches), so a lost device can be cut
  off by rotating the key.
- Cookies issued before this release (3-segment tokens) still validate and are
  treated as remembered, so no one is force-logged-out by the upgrade.

## Tests

Access-control suite extended to **36 checks** (remember=1 token + ~30-day
lifetime, remember=0 session token, legacy 3-segment cookie still valid,
sliding refresh extends an active remembered device but leaves a session cookie
alone). Full suite green.
